## 三、P0 需要共同确定的事项

1. 国内样例：上海，使用豫园、城隍庙片区、外滩、同名分店等作为身份与空间样例。
2. 海外样例：新加坡，用户已明确暂缓国外测试；不属于当前 P0 完成条件。国内样例为上海。
3. 账号：用户已提供 dltrip 的高德 Web 服务 Key，仅保存在被 Git 忽略的 backend/.env，变量 AMAP_WEB_SERVICE_KEY；上海查点、详情、周边和步行/公交/驾车已实测。Google 凭据与高德海外权限留至海外阶段；当前无需补充。前端高德 JS API 凭据在 P3 再配置。
4. 调用边界：先确认账户计费、配额和允许的试验预算；不自动开通付费套餐。脚本设调用次数上限，不自动运行大矩阵。
5. 第一轮交通范围：步行、公共交通、驾车；骑行、实时订票、完整前端地图暂缓。

### P0.2 新建共享数据契约

| 拟新增文件 | 本阶段具体内容 |
|---|---|
| backend/app/schemas/intent.py | TripIntent；日期、城市、旅行者、交通偏好、预算/币种；硬条件和软偏好分开；字段来源、确认状态；引用画像快照 |
| backend/app/schemas/place.py | Place、ProviderRef、Coordinates；内部 ID、供应商 ID、类别、原始坐标系；别名、片区关系和身份匹配状态；数据来源及获取时间 |
| backend/app/schemas/plan.py | Visit、RouteLeg、Stay、PlanVersion；地点引用、时区、停留、出发到达、距离耗时、路线状态、锁定项与版本 |
| backend/app/schemas/action.py | 按动作类型区分参数的 AgentAction；ToolResult 成功/失败/部分结果；request_id、base_version 与可读目的 |
| backend/app/schemas/session.py | 会话状态、需求快照引用、待回答问题、Selection、状态版本；仅定义结构，P1 实现持久化 |

规则：距离用米、耗时用秒；经纬度显式命名；坐标系不可省略；时间带时区；金额带币种。未知值为 null 并附原因，不用 0 伪装未知。
地点同名不自动合并；供应商 ID 不充当跨供应商统一 ID；片区与内部景点有关联但不等价。
动作类型先定义 ask_user、search_candidates、get_place_details、compute_itinerary、rank_nearby、edit_plan、validate_plan、finish；P0 不接通 Agent 循环。
合成样例明确标为 fixture，不在产品页面显示成真实结果。
当前结果：五份 schema 与 common.py 已新增；test_p0_contracts.py 的 23 项测试通过。Windows 时区数据库通过 tzdata 依赖提供。模型尚未接入旧生成入口；P1/P2 继续集成。

### P0.3 地图最小适配与探测

| 拟新增/修改文件 | 本阶段具体内容 |
|---|---|
| backend/app/providers/maps/base.py | 能力声明、地点搜索/详情、单段路线协议；不支持、无路线、限流、权限不足等不同错误 |
| backend/app/providers/maps/amap.py | 上海样例所需最小搜索与步行/公交/驾车接口；保留来源、原坐标和响应状态 |
| backend/app/providers/maps/google.py | 海外最小 Places/Routes 探测适配；账号/城市确认后实现和验证；不承诺完整海外产品 |
| backend/app/providers/maps/policy.py | 根据已核实条款记录可缓存字段、期限、显示归属及配套底图要求；未确定内容不长期存储 |
| backend/app/config.py | 服务端地图配置、超时、试验调用上限；读取环境变量 |
| backend/.env.example | 仅变量名和说明；服务端 Key 不传给前端 |
| backend/scripts/probe_maps.py | 显式执行的有界探测；指定城市/供应商/模式；输出脱敏摘要；默认不循环重试或扩大全矩阵 |
| docs/p0/map-probe-report.md | 记录运行时间、环境、目标、模式、结果、延迟、缺字段与失败原因；无凭据时标记 blocked |

API 字段和账号实际权限在实施时重新查官方文档。P0 不自动选择任意供应商作为降级，不混用不同坐标系，不把 Google 路线画在其他底图。
建议每个城市选 3 个明确地点，测少量有方向的路线；公共交通记录实际查询日期与出发时刻。公交不可用时明确能力不足，不自动当步行成功。
P0 保存协议与允许保存的摘要，不长期归档全部供应商原始响应。
当前结果：amap/google/base/transport/policy 已实现；probe_maps.py 可显式运行。上海最终单轮 11 次请求，三模式有覆盖，短段无公交明确返回 no_route；公交几何嵌套已修复。新加坡缺 Google 凭据，0 次请求。完整报告：docs/p0/map-probe-report.md。

### P0.4 契约校验与关闭决策

完成清单：P0.1 字段盘点；P0.2 可运行契约；P0.3 上海高德查点、详情、周边及三模式探测；P0.4 离线/实测证据与完成结论，均已交付。

前端类型方案：P1 正式接口建立后，以其 OpenAPI 为基准生成/校验类型。上海单段试验不等于全国覆盖或五日旅行质量验收；更多城市、地点归并和完整行程质量归 P2，地图卡片交互归 P3。

## 五、P0 的范围边界

- 本阶段建立可验证的数据基础和最小供应商样例，不迁移数据库、不搬迁所有 Agent、不重写现有 /api/plan。
- 当前国内地图凭据及实测齐全，P0 按国内范围完成。海外凭据缺失仍属未来验证事项，不伪造海外成功，也不阻塞国内开发。
- 前端地图 SDK、卡片、路线绘制在 P3 集成；P0 提前验证其供应商展示要求，避免后续返工。
- 排序公式、复杂路线求解器、酒店实时库存不在 P0。明确预留字段与能力边界即可。
